## 一、范围决策：不做实时仿真

**决策**：项目不做 Speedgoat 实时执行复现，定位为"离线高保真仿真 + 多目标优化"。

**依据**

1. 基准论文的实时部分是在 Speedgoat P3 上以 0.1 s 固定步长运行模型，报告 0.07 s 单步延迟、约 30% 实时余量，并明确说明 "without external hardware coupling"、没有物理 I/O。这是执行性能演示，不是 HIL，也不影响 EMS 对比、退化计算和 TLC 结论。
2. 本机 MATLAB R2018b 的 Simulink Desktop Real-Time 内核（`rtwtkrnl.sys`，2018 年版本）在 Windows 11 26200 上执行 `sldrtkernel -setup` 会触发蓝屏（bugcheck 0x1E，`STATUS_ILLEGAL_INSTRUCTION`，2026-11-13 19:49 实测），复现风险高且无科研价值。

**对外表述**：可用"离线高保真仿真 + 多目标优化（降阶代理单趟评估约 1–2 ms，远小于 0.5 s 仿真步长）"，不要写"复现实时仿真系统"，也不要拿实时余量当卖点。

## 二、实现修正

审计发现三类问题：经济性计算存在多份互相不一致的副本、代理模型与 MATLAB 口径漂移、缺少可行性约束。全部修正如下。

### 1. `CAPEX_FC` 未随决策变量缩放

- 旧：`CAPEX_FC = 190 * P_nom_base / 1000`，始终按 820.3 kW 计价。
- 新：`CAPEX_FC = 190 * P_nom / 1000`，`P_nom` 为决策变量。
- 影响：旧版系统性地低估小电堆方案的成本优势，前沿上"降低 FC 定容"的收益被抹掉。

### 2. 怠速判据硬编码

- 旧：`if fc_on and P_fc <= 250000.0: t1 += dt`。
- 新：`if fc_on and P_fc <= P_idle + 50000.0: t1 += dt`。
- 依据：`compute_degradation.m` 使用 `P_idle + 50 kW`；`P_idle` 是决策变量，硬编码 250 kW 会让两套实现再次漂移。

### 3. 电池放电电流用固定电压

- 旧：`I_bat_deg = P_bat / 1500.0`。
- 新：使用与 SOC 更新相同的实际开路电压 `I_bat = P_bat / Uocv(SOC)`。
- 依据：`compute_degradation.m` 为 `I_batt = P_bat ./ max(V_batt, 1)`；低压端用 1500 V 会低估安时吞吐。

### 4. OPEX 年趟数

- 旧：`730`（按天算）。
- 新：`journeys_per_year = 14400 / 20 = 720`（论文 2 趟/天 × 360 天）。
- 影响：OPEX 约 +1.4%，与 CAPEX 量级相比影响不大，但口径必须一致。

### 5. 缺少可行性约束

- 新增：`SOC_min >= 0.30`（论文 Sec. 3.1），违反时三个目标同时加常数惩罚（`1e8 / 1e3 / 1e3`），保证不可行解被所有可行解支配。
- 实测：在当前决策箱内 200 个随机样本的 `SOC_min` 最低为 0.316，约束实际上未被激活；惩罚分支用测试覆盖（临时抬高阈值）。

### 6. `verify_pareto.m` 的成本函数副本

- 旧：脚本内置 `pareto_econ`，复制了上述全部 bug，且 `CAPEX_FC` 写死 820.3 kW。
- 新：删除副本，改为构造 `sim_data`（含 `Vbatt_log`）后调用唯一的 `compute_degradation.m`；FC 参数按回填后的 `FC_nom / P_idle` 覆盖。
- 附带：前沿点不再硬编码，直接从 `results/pareto_front_v2.csv` 取 TLC 最小/中位/最大三个点，另加 EMS1 基线；输出 `results/verification_v2.csv`。

### 7. 仓库卫生

- 删除 `compute_degradation_fixed.m`（文件名与函数名不一致，且含旧口径），仓库内只保留 `compute_degradation.m`。
- 新增 `tests/test_pipeline.py`（4 项：基线复现、Wang 模型闭式一致性、前沿非支配性、惩罚机制）。

## 三、口径澄清（电池更换次数）

旧文档写"论文的电池更换数与自己的 SOC 曲线矛盾"。**该表述过度**，更正如下。

1. 按 Wang 2011 的累计放电安时口径，本项目每趟约 1.0 个等效满放循环，20% 容量损失对应约 2042 循环，故约 7.0 次更换。
2. 论文 1.57 次反推为每趟约 0.22 个等效循环。
3. 论文 SOC 从 0.90 降到 0.423，仅净放电就有

   `0.477 × 1178.61 Ah ≈ 562 Ah`，约 843 kWh，折合 `843 / 1767.9 ≈ 0.48` 个等效满放循环。

4. 0.22 ≈ 0.48 的一半。

**结论**：论文的循环计数符合"一次充放（充+放）算一个等效循环"（EFC ≈ 净放电/2）的惯例，而 Wang 模型统计的是累计放电吞吐。两者相差约一倍来自**口径**，不是论文自相矛盾，也不是本项目算错。论文未声明口径，因此不可直接比较；仓库保留物理自洽的累计放电口径，并在 `compute_degradation.m` 里同时输出 `cycles_equiv`、`Ah_discharge`、`N_life` 供核对。

基线（EMS1，`x = [0.30, 0.70, 1.0, 200/820.3, 0.90]`）：

| 指标 | 修正前 | 修正后 | 论文 |
|---|---|---|---|
| H2 / 趟 | 106.6 kg | 106.62 kg | 105.8 kg |
| TLC | 9.32M EUR | 9,332,345 EUR | 9,191,965 EUR |
| FC 更换 | 1.95 | 1.95 | 2.5 |
| 电池更换 | 7.54 | 7.03 | 1.57 |
| SOC 终点 | 0.522 | 0.522 | 0.423 |

前沿（40 点，`seed=0`）：

| 目标 | 范围 |
|---|---|
| TLC | 8,630,774 – 9,672,164 EUR |
| FC 更换 | 1.89 – 2.10 |
| 电池更换 | 6.62 – 7.53 |

- 代理模型上 4 个前沿点严格支配 EMS1，最优者 TLC 低 1.10%（9.23M），FC 和电池更换次数同时略低。
- 目标间相关系数：`FC_nom`–TLC = +0.995，`FC_nom`–电池更换 = −0.999，说明前沿近似一维定容权衡。
- `FC_nom_scale = 0.85`、`SOC_low = 0.20`、`SOC_high = 0.85`、`SOC_regen = 0.95` 触界，说明约束范围限制了收益。

### 高保真回填（2026-11-13 实测，`results/verification_v2.csv`）

| 点 | TLC 代理 → Simulink | 误差 | FC 代理 / Sim | 电池代理 / Sim |
|---|---|---|---|---|
| Pareto 1 | 8,630,774 → 8,578,142 | −0.61% | 1.89 / 1.89 | 7.53 / 8.07 |
| Pareto 2 | 9,265,694 → 9,195,557 | −0.76% | 1.94 / 1.94 | 6.96 / 7.46 |
| Pareto 3 | 9,672,164 → 9,505,299 | −1.73% | 2.10 / 2.24 | 6.62 / 7.10 |
| EMS1 基线 | 9,332,345 → 9,202,171 | −1.39% | 1.95 / 1.95 | 7.03 / 7.54 |

- TLC 代理高估 0.6%–1.7%；FC 更换误差 ≤ 0.14 次。
- 电池更换代理**系统性低估 7.1%–7.2%**：代理用 `I = P/Uocv`，Simulink 计入内阻与二阶 RC 压降。偏差近似统一乘性系数，排序不受影响，绝对值乘 1.072。
- **支配性结论要降级**：高保真下 3 个代表点中只有 Pareto 2 严格支配 EMS1（TLC −0.07%、电池 −0.08 次）；Pareto 1 的 TLC 低 6.8%，但电池更换 +0.5 次，属于权衡而非支配。对外应说"EMS1 接近前沿，改进空间主要在电堆定容"，不要说"EMS1 被显著支配"。
- Simulink 闭环基线 TLC 9,202,171 对论文 9,191,965 的偏差仅 +0.11%，耗氢 106.00 kg 对 105.8 kg 偏差 +0.19%。

## 四之二、算法基准（2026-11-13 追加）

同一模型、同一决策空间、2 360 次评估、3 个种子，`benchmark_algorithms.py`：

| 算法 | HV | IGD | 用时 |
|---|---|---|---|
| MOPSO | 0.7886 ± 0.0028 | 0.0089 | 4.6 s |
| SPEA2 | 0.7740 ± 0.0009 | 0.0241 | 3.9 s |
| NSGA-II | 0.7528 ± 0.0038 | 0.0525 | 3.6 s |
| MO-MRFO | 0.7485 ± 0.0062 | 0.0482 | 7.1 s |
| MOEA/D | 0.7215 ± 0.0169 | 0.0841 | 5.4 s |

- **MO-MRFO 不占优**，与 NSGA-II 同级，低于 MOPSO/SPEA2。对外不要写"提出了更优算法"。
- MOEA/D 必须先做目标缩放（TLC/1e6），否则被 1e6 量级的成本目标拖垮（HV 0.08 → 0.72）。
- 决策空间扫描：`FC_nom_scale = 0.80` 时 SOC_min = 0.269（不可行），`0.85` 时 0.319（可行）。**电堆处在"再小就带不动"的可行性边界**，这是 TLC 只能优化约 7% 的根本原因，与算法无关。
- 若要显著提升优化收益，只能改问题本身（增加电池容量/储氢量为决策变量、多线路工况、放宽 SOC 下限），而不是换算法。

## 四之三、协同定容实验（2026-11-13 追加）

按上述结论扩展决策空间：增加第 6 个变量 `bat_scale`（电池容量 / 1178.61 Ah，范围 0.6–4.0），电堆定容下界放宽到 0.30×（246 kW），上下界见 `experiment_codesign.py`。

**质量反馈**：大电池必须付出质量代价。`mrfo_multiobjective_v2.py` 新增 `BATT_MASS = 8920 kg`（论文 Table 10 的电池包质量）与 `route_profile(m_train)`；`evaluate` 在 `bat_scale ≠ 1` 时按 `M + (bat_scale−1)·BATT_MASS` 重算牵引/再生功率。`bat_scale = 1` 走原预计算数组，五变量结果逐位不变（基线仍为 9,332,345 EUR）。

**结果**（MOPSO + NSGA-II × 3 seeds，每种子 8 000 次评估；合并 6 个档案后重新非支配筛选，511 点）：

| 指标 | 五变量 | 六变量 |
|---|---|---|
| TLC 最小 | 8,630,774 | **6,841,500（−26.7%）** |
| 电堆功率 | 697–902 kW | 246–764 kW |
| 电池容量 | 1,178.61 Ah | 2,964–4,714 Ah |
| FC 更换 | 1.89–2.10 | 1.68–1.97 |
| 电池更换 | 6.62–7.53 | 0.82–2.00 |

最便宜设计：FC 246 kW、电池 2,964 Ah、SOC_low 0.263、SOC_high 0.785、怠速 123 kW、SOC_regen 0.899；单趟耗氢 24.1 kg，电池更换 2.00 次。

**必须同时写出的限制**：

1. 前沿 79% 的解落在 `FC_nom_scale=0.30` 下界附近，但目标在该区间几乎是平的：固定最便宜设计的 SOC 参数，把电堆从 123 kW 扫到 328 kW，TLC 只在 6.857M–6.991M 之间变化（最小值 6.842M 在 246 kW）。H2 随电堆变小而降低，电池更换次数同时升高，二者抵消。结论是"固定电池容量切掉了设计空间、低 TLC 端对电堆定容不敏感"，而不是"电堆越小越好"。
2. 电池超过约 4× 后 SOC 全程高于状态机的 60% 恢复阈值，电堆永不离开怠速（相同 `bat_scale` 下不同 FC 定容给出完全相同的 H2）。这是固定 EMS1 的退化区，所以上界取 4.0×。
3. REPLEX 用 `floor`，容量微调可使 20 年内电池更换次数 1↔2 跳变，TLC 跳变约 17 万欧元（6.84M 与 7.01M 只差这一次更换）。对外报"约 6.8–7.0M，−25%～−27%"。
4. 电池寿命的容量缩放来自论文 Eq. (14) 的写法（`N_cyc_EoL ∝ C^0.786`），口径变化会改变结论，尚未做敏感性分析。
5. 代理模型没有电池功率/C-rate 上限；协同定容点也未做 Simulink 回填（闭环模型的电池容量与整车质量需要同步改参数，超出当前标定范围）。

## 六、仍未解决的问题

- 五变量主实验单种子运行；算法基准已做 3 种子 HV/IGD，协同定容也做了 3 种子，但主前沿仍是 `seed=0`。
- 前沿接近一维，三目标信息的实际价值有限。
- 代理模型在标定工况外（FC 定容 < 0.85×、电池容量 ≠ 1×）未做 Simulink 回填，扩大边界的结论只在代理模型内成立。
- 协同定容暴露了固定 EMS1 控制律与电池容量的耦合：电池很大时电堆长期怠速。要把协同定容做成可信结论，需要同时优化控制律（或改用等效消耗最小等策略），并把电池 C-rate/功率上限加入模型。
